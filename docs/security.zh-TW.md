# 安全性

[English](security.md)

AnswerWall 保護什麼、怎麼保護，以及哪些部分要由你負責。工程細節在 [DECISIONS.md](DECISIONS.md) 第 7 節（英文）；伺服器的所有選項在 [apps/server/README.md](../apps/server/README.md)（英文）。

## 設計的前提

一個人，在這個人自己掌控的機器上使用。沒有使用者帳號，也沒有角色之分。已配對的裝置可以做任何事：以你的廠商帳號送出提問、讀取全部的歷史紀錄、更改設定、新增端點、配對更多裝置。

它無法防範：能讀取資料目錄或使用你作業系統帳號的人（資料庫沒有加密）、你配對之後遺失卻沒有撤銷的裝置，以及廠商 CLI 以執行它的使用者權限所做的事。

## 登入

- 登入無法關閉。來自同一台機器的請求和其他請求一樣要登入。
- **第一台裝置。** 還沒有配對任何裝置時，伺服器啟動時會把一組 8 位數的一次性配對碼寫到記錄（log）。用同一個資料目錄執行 `answerwall pair`，隨時可以取得新的配對碼。
- **其他裝置。** 在已登入的裝置上使用**設定 > 裝置 > 建立配對碼**。
- 配對碼 5 分鐘內有效、只能用一次，輸入錯誤 5 次即作廢。
- 最多 8 台裝置。每台裝置有自己的隨機權杖；伺服器只儲存它的 SHA-256。**撤銷**會讓該裝置立即登出，並切斷它開著的回答串流（提問本身會繼續執行）。**登出**對你正在使用的裝置做同樣的事。
- 瀏覽器把權杖放在指令碼讀不到的 cookie 裡，只會送往同一個網站，連線是 HTTPS 時會標示為 secure。它的有效期是最後一次使用後 400 天。
- 失敗的嘗試限制為每個位址每分鐘 10 次（可調整）。
- `ANSWERWALL_TOKEN` 可以設定一組給自動化用的固定權杖。它不需要配對就能登入，所以請把它當成密碼看待；除非需要，否則不要設定。
- 權杖絕不會出現在網址或記錄中。

**本機模式的 Windows 應用程式**做法不同：它的伺服器在 `127.0.0.1` 的隨機連接埠上聆聽，只接受每次啟動時重新產生的權杖，這個權杖由應用程式本身在頁面之外加到請求上。它沒有已配對的裝置，也拒絕建立配對碼。

## 網路暴露範圍

- 除非你設定 `ANSWERWALL_HOST`，伺服器會綁定 `127.0.0.1`。Docker 的 compose 檔預設把連接埠發布在 `127.0.0.1`，除非你修改。
- 每個請求指名的主機都必須是伺服器認得的：迴路位址的名稱，或 `ANSWERWALL_PUBLIC_ORIGINS` 中的其中一個。每個會更動資料的請求，都必須來自伺服器自己的頁面。其他來源的網頁完全無法存取。唯一的例外是你自己列出的瀏覽器擴充功能，而且只在網頁儲存格開啟時有效；見[網頁儲存格與瀏覽器擴充功能](#網頁儲存格與瀏覽器擴充功能)。
- **純 HTTP 只留在本機。** TLS 關閉且綁定非迴路位址時，會拒絕來自其他機器的連線，只有你列在 `ANSWERWALL_TRUSTED_PROXIES` 的反向代理例外。`ANSWERWALL_ALLOW_INSECURE=1` 會解除這項限制；這時網路路徑上的任何人都能讀到你的提問、回答與登入狀態，而且只要這個設定還在，頁面就會持續顯示警告。

### HTTPS

三種做法，依我們會嘗試的順序排列：

1. **由反向代理持有憑證**（`ANSWERWALL_TLS=off`、`ANSWERWALL_PUBLIC_ORIGINS`、`ANSWERWALL_TRUSTED_PROXIES`）。只有來自所列代理位址的轉送標頭才會被採信。[apps/server/README.md](../apps/server/README.md#behind-a-reverse-proxy) 有一段 nginx 設定範例。回答是串流傳送的，所以代理不可以緩衝。
2. **你自己的憑證**（`ANSWERWALL_TLS=cert`，搭配 `ANSWERWALL_TLS_CERT` 與 `ANSWERWALL_TLS_KEY`）。憑證檔更新後不需重新啟動就會生效。
3. **自動產生的私有憑證授權單位**（`ANSWERWALL_TLS=auto`）。伺服器會建立一個 CA，並為自己的名稱簽發憑證。每台裝置都必須安裝一次 CA 憑證：**設定 > 連線安全**提供 `answerwall-ca.crt` 下載，並附有 Windows、macOS、iPhone 與 iPad、Android 與 Linux 的安裝步驟。這個檔案不含私密金鑰。安裝 CA 是實實在在的信任行為：請像保管任何私密金鑰一樣，保管好伺服器的資料目錄。

手機必須透過 HTTPS、而且信任該憑證，才會願意把頁面安裝成應用程式。

## CLI

大部分的風險在這裡。AnswerWall 會用各 CLI 所提供的最嚴格方式、在空目錄中執行它，並從 CLI 的環境中移除 AnswerWall 自己的變數，以及（預設）API 金鑰變數。剩下的部分因 CLI 而異：

| CLI        | 由 AnswerWall 執行時，模型可用的工具                                           |
| ---------- | ------------------------------------------------------------------------------ |
| `claude`   | 關閉。已用真實 CLI 確認。                                                      |
| `codex`    | 幾乎全部關閉；剩下的在唯讀沙箱中執行。已用真實 CLI 確認。                      |
| `agy`      | 不受限制。模型可以用執行伺服器的使用者權限採取行動。                           |
| `grok`     | Linux 與 macOS 上是唯讀沙箱（CLI 能套用的話）。Windows 上不受限制。            |
| `opencode` | 關閉，透過一個拒絕所有權限的代理。已在 Linux 上以真實 CLI 對本機測試端點確認。 |

有工具的模型，可能被它讀到的文字說服去使用工具，包括你貼進提問裡的文字。對 `agy`，以及 Windows 上的 `grok`，請假設你的使用者能讀取或修改的任何東西都在它的活動範圍內。

- **在 Docker 中，容器就是邊界。** 只掛載資料 volume 與 CLI 的家目錄 volume（使用自己的憑證時，另外以唯讀方式掛載憑證目錄），絕不掛載你的家目錄，而且程序不以 root 執行。無法關閉工具的 CLI 就該在這裡執行。
- **在 Windows 上沒有這樣的邊界。** 本機模式下，CLI 以你的身分執行。
- 開啟**允許網路搜尋**時，模型會讀到由搜尋引擎挑選的網頁。AnswerWall 只啟用在廠商伺服器上執行的搜尋，絕不啟用會從你的機器擷取網址的工具。

各 CLI 的細節：[providers.zh-TW.md](providers.zh-TW.md)。

## 網頁儲存格與瀏覽器擴充功能

預設關閉，而且擴充功能尚未隨任何版本發布；這裡說明的是已經存在的伺服器端。

網頁儲存格會在 AnswerWall 瀏覽器擴充功能的牆面頁面中，顯示網站自己的網頁應用程式，使用的是你已登入該網站的瀏覽器。**設定 > 網頁儲存格**有一個總開關、兩個分開的開關控制擴充功能在網站上可以做的事（填入提示；讀取回答）、可以連線的擴充功能 ID，以及網站清單。

- **誰可以連線。** 擴充功能的頁面是伺服器唯一接受的其他來源用戶端，只在網頁儲存格開啟時、而且只對你列出的擴充功能 ID 有效。沒有萬用字元。伺服器仍然不會對任何人送出跨來源（CORS）許可，所以不論是否列了擴充功能，其他來源的網頁都讀不到任何東西。
- **它怎麼登入。** 和其他裝置一樣：用配對碼。它會得到自己的權杖，存放在擴充功能的儲存空間（網頁讀不到），並隨每個請求送出。它永遠不會拿到 cookie，而且來自擴充功能、卻帶著 cookie 的請求會被拒絕。它會出現在**設定 > 裝置**，也在那裡撤銷。
- **列出的擴充功能能做什麼。** 已配對裝置能做的一切。請只列出你自己從這個儲存庫安裝的擴充功能。瀏覽器會在會更動資料的請求上標明擴充功能，清單就是在這些請求上檢查的；讀取則一律需要權杖。
- **清單做不到的事。** 只要瀏覽器讓某個擴充功能存取伺服器的位址，不論它有沒有列在這裡，它都能讀取並更改伺服器自己的頁面，就像它對任何網站一樣。沒有任何伺服器能防止這件事。請不要在用來開 AnswerWall 的瀏覽器裡安裝你不信任的擴充功能。
- **網頁儲存格的回答**是擴充功能從網頁讀到的文字。它和其他回答受到同樣的對待：以文字儲存，進入頁面之前先經過清理。只有建立該次提問的裝置可以送出它的網頁回答，每格一次，並受時間上限與回答大小上限限制；任何裝置都可以取消。
- **伺服器不做的事。** 它從不連線到這些網站，看不到你在這些網站的登入，也看不到它們的 cookie。
- **條款。** 這些網站對自動化存取其網頁應用程式的限制，比對命令列工具的限制寫得更明確。這就是為什麼填入提示與讀取回答是兩個分開、預設關閉的開關。AnswerWall 不對任何網站的條款准許什麼作任何說明。

## 回答與頁面

回答是不可信的文字。它們會以 Markdown 呈現，並在進入頁面之前經過清理：指令碼與 `javascript:` 連結會被移除，圖片不會載入（變成連結），連結會在應用程式之外開啟，而且不會把頁面的位址帶過去。內容安全政策只允許來自伺服器本身的指令碼、樣式、圖片與連線，並禁止被嵌入框架。

## 機密資料

- OpenAI 相容端點的 API 金鑰與 TLS 私密金鑰放在 `secrets.json`，與資料庫分開。在 Linux 與 macOS 上，只有執行伺服器的帳號可以讀取這個檔案。在 Windows 上直接執行的伺服器，依靠的是資料目錄的權限，所以請把資料目錄放在你的使用者設定檔之內。Windows 應用程式則把金鑰放在它自己的檔案中，由 Windows 針對你的使用者帳號加密；無法加密時什麼都不會儲存。
- 頁面可以設定或刪除金鑰，但永遠無法讀回。
- 已儲存的金鑰綁定在輸入當時的位址；透過環境變數提供的金鑰，只會送到你在旁邊指名的來源。見 [providers.zh-TW.md](providers.zh-TW.md#從環境變數提供金鑰)。
- CLI 的登入資訊不是 AnswerWall 的機密：它從不讀取。

## 限制

**設定 > 限制**裡是一些上限，避免錯誤或外洩的權杖無止境地啟動程序。預設值：每次提問 32 格、同時 4 個提問、佇列 64 格、每個回答 5 分鐘、每個提問 200 KiB、每個回答 2 MiB。每一項都有伺服器強制執行的硬性上限。

## Windows 安裝程式沒有簽章

Windows 無法告訴你它是誰建置的。請只從這個儲存庫的 Releases 頁面下載，並與同一版本的 `SHA256SUMS` 比對。雜湊值只能證明檔案就是發布流程建置出來的那一個，不能證明是誰寫的。SmartScreen 與智慧型應用程式控制的說明見 [README](../README.zh-TW.md#未簽章的-windows-版本)。

## 回報安全漏洞

請不要為安全問題開公開的 issue。請使用[儲存庫](https://github.com/onlyfly34/answerwall/security)的 **Security > Report a vulnerability**，它會把報告私下送給維護者。
