# 在真實網站上檢查網頁儲存格

[English](verify-web-cells.md)

網頁儲存格的自動化測試只針對一個替身網站。真實網站（claude.ai、chatgpt.com、gemini.google.com、grok.com、chat.z.ai）的規則，沒有任何一條在該網站上執行過：這些規則是依頁面公開可見的結構撰寫的。這份清單說明擁有自己帳號的人如何逐一檢查各個網站，以及發現不符時該回報什麼。

這些網站的條款限制以自動化方式存取其網頁版。下面的 D 與 E 兩個步驟，會為了幾個提問而開啟那兩個自動化開關。要不要這樣做、在哪些網站、用哪個帳號，由你自行決定；A 到 C 不需要任何一個開關。這裡的任何內容都不表示任何步驟是任何網站所允許的。

所需時間：每個網站約 10 分鐘。請使用簡短的提問；每個網站三個就夠了。

## 開始之前

- 一台執行中的 AnswerWall 伺服器（發行版；不是本機模式的 Windows 應用程式），以及一台已登入它的裝置。
- Chrome 或 Edge，並且已**在一般分頁**登入你要檢查的網站。
- 與伺服器同一個發行版的 `answerwall-extension-<版本>.zip`，已與 `SHA256SUMS` 比對並解壓縮。

請為回報記下：版本、瀏覽器與其版本、作業系統、日期，以及每個網站你使用的方案（免費或付費），因為頁面會因此不同。

## A. 安裝與配對（一次）

1. `chrome://extensions`（或 `edge://extensions`）> 開啟**開發人員模式** > **載入未封裝項目** > 選取解壓縮後的資料夾。
   - [ ] 擴充功能顯示為「AnswerWall web cells」，ID 是 `nffcmlcjkacklpololkpdmhcfokannom`。
   - [ ] **詳細資料 > 權限／網站存取權**列出那五個網站，沒有類似「所有網站」的項目。
2. 點選擴充功能在工具列上的圖示。
   - [ ] 開啟首次設定頁面，並顯示同一個 ID。
3. 在伺服器上：**設定 > 網頁儲存格** > 開啟**允許網頁儲存格**、勾選要檢查的網站、加入這個 ID。**填入提示**與**讀取回答**先保持關閉。
4. 在首次設定頁面輸入伺服器位址與配對碼，按下**連線**。
   - [ ] 瀏覽器詢問是否允許擴充功能存取伺服器的位址，而且只提到那一個位址。
   - [ ] 牆面出現。伺服器的**設定 > 裝置**列出「瀏覽器擴充功能」。
   - [ ] 伺服器上的 ID 填錯時（刪掉一個字母），**連線**會說明伺服器拒絕此擴充功能。

請在回報中註明伺服器是在 `http://127.0.0.1`、區域網路上的純 HTTP，還是 HTTPS（公開憑證，或伺服器自己的憑證授權單位）：自動化測試只涵蓋 loopback 的 HTTP。

## B. 嵌入，每個網站（兩個開關都關閉）

在擴充功能的牆面上為該網站新增一個格子（**新增格子**，把供應商選成該網站）。

- [ ] 網站的頁面出現在格子裡，已登入，看起來和在分頁中一樣。如果看到的是瀏覽器的拒絕頁面、空白框架，或是你明明已在分頁登入卻出現網站的登入頁：記下格子顯示的內容，這個網站就檢查到這裡。
- [ ] 幾秒內格子顯示**已連接頁面**，以及**規則未驗證**。
- [ ] 在格子裡手動輸入並送出提問可以運作，包括你會用到的網站自有功能（模型選擇、附件、搜尋）。
- [ ] **在分頁中開啟**會在新分頁開啟該網站；**重新載入**會讓格子回到網站的起始頁面。
- [ ] 在一般分頁登出該網站，重新載入格子：它顯示網站的登入頁。在格子裡登入可以成功，或（Gemini）會前往格子無法顯示的其他主機；請記下是哪一種。之後請在一般分頁重新登入。

## C. 必須維持原狀的部分（一次，任選一個網站）

- [ ] 牆面開著時，在一般分頁開啟同一個網站。它的行為一如往常。在它的開發人員工具中（**Network**、頁面本身的文件、**Response Headers**），如果網站有送出 `content-security-policy` 或 `x-frame-options`，它仍然存在。
- [ ] 在那個一般分頁的開發人員工具 **Console** 中，執行環境選單會列出擴充功能的內容指令碼，但頁面沒有任何變化：在牆面按下送出時，那裡不會出現任何提問。
- [ ] 關閉牆面分頁。在 `chrome://extensions` 的**檢查檢視畫面：Service Worker** 的主控台執行 `await chrome.declarativeNetRequest.getSessionRules()`：結果是 `[]`。牆面開著時則恰好有一條規則，它的 `tabIds` 是牆面所在的分頁。

## D. 填入提示，每個網站

開啟**填入提示**（**讀取回答**保持關閉）。從牆面的輸入區提問 `Reply with the single word: ready`。

- [ ] 提問出現在網站的輸入框中，並且只送出一次。
- [ ] 格子顯示**已在頁面中送出。「讀取回答」已關閉，因此不會儲存任何內容。**，而且**歷史紀錄**中這次提問沒有該網站的項目。
- [ ] 含有兩行與非拉丁文字的提問（例如 `第一行` / `second line`）送到網站時與輸入的一致。

如果格子回報規則找不到輸入框或可用的送出按鈕，請看「回報失敗的規則」。

## E. 讀取回答，每個網站

把**讀取回答**也開啟。提問三件事：

1. `Reply with the single word: ready`
2. `Give me a numbered list of three fruits, then a table with two columns, then a Python hello world in a code block.`
3. 一個在該網站需要超過 20 秒才能回答完的提問（一篇長文，或會先思考的模型）。

對每一個提問：

- [ ] 格子依序顯示**正在把提示輸入頁面…**、**等待頁面完成回答…**、**完成。回答已存入歷史紀錄。**
- [ ] 儲存的回答（**歷史紀錄** > **開啟**）是該提問的完整回答：沒有提早截斷、不是前一個回答，也沒有夾雜按鈕文字（「Copy」「Retry」）或網站自己的介面文字。
- [ ] 第 2 個提問：清單、表格與程式碼區塊（含語言）都還原成 Markdown。
- [ ] 第 3 個提問：頁面完成之前沒有儲存任何內容。
- [ ] 在長回答進行中按下格子的**取消**：格子以已取消結束，沒有儲存任何內容，頁面自己繼續進行。

接著關閉**填入提示**，保留**讀取回答**：

- [ ] 從牆面送出：格子請你在頁面中輸入。在那裡手動輸入並送出；完成的回答會被儲存。

## F. 把規則標示為已驗證

某個網站的 A 到 E 都通過後，在一個 pull request 中把規則檔 `apps/extension/rules/<site>.json` 改成 `"verified": true` 與 `"verifiedOn": "<日期，YYYY-MM-DD>"`，並註明檢查時使用的瀏覽器、版本與方案。之後格子就不再顯示「規則未驗證」。規則的驗證只對當天的頁面有效；網站改版不會事先通知。

## 回報失敗的規則

請開一個 issue，內容包含：

- 網站、日期、瀏覽器與其版本、作業系統、擴充功能的版本，以及你使用的是免費或付費方案；
- 哪一個步驟失敗，以及格子顯示的確切訊息；
- 規則本來應該找到什麼。在格子裡對該元素（輸入框、送出按鈕、一整個回答、網站回答期間看得到的「停止」按鈕）按右鍵 > **檢查**，並為每個元素複製：標籤名稱，以及它的 `id`、`class`、`data-*`、`aria-label` 與 `role` 屬性，再加上它往上兩三層父元素的同樣資訊。請在網站回答期間做一次、回答完成後再做一次，因為規則需要兩者的差異；
- 如果是儲存的回答不對：儲存了什麼，以及頁面實際顯示什麼。

**請不要包含**任何個人資料：不要 cookie、不要權杖、不要對話內容、不要帳號名稱、不要你的伺服器位址，也不要顯示出這些內容的螢幕截圖。頁面本身結構的屬性名稱與屬性值就足夠了。

規則往往只要修改它的資料檔（`apps/extension/rules/<site>.json`：清單會依序嘗試，使用第一個相符的選擇器）並重新載入擴充功能就能修好。如果你試出了有效的選擇器，請在 issue 中說明。

## 請回覆的內容

每個網站、每個步驟一行就夠了：

```
claude    A ok  B ok  C ok  D ok  E fail（儲存的回答夾雜 "Copy"）
chatgpt   A ok  B fail（框架被拒絕）
```

再加上版本、伺服器位址的種類，以及任何這份清單沒有預料到的情況。
